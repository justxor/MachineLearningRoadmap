## 🧱 Базовые понятия ML

**Machine Learning (машинное обучение, ML)** — построение моделей, которые обучаются на данных и делают предсказания на новых. Противопоставляется явному программированию правил. См. [data-science/13-ml-canvas.md](./data-science/13-ml-canvas.md).

**Supervised learning (обучение с учителем)** — модель учится на парах «вход → правильный ответ». Самый распространённый сетап (классификация, регрессия). Пример: предсказать цену квартиры по характеристикам.

**Unsupervised learning (обучение без учителя)** — модель ищет структуру в данных без меток. Кластеризация, снижение размерности, anomaly detection. Пример: разбить клиентов на сегменты без заранее заданных групп.

**Self-supervised learning** — модель сама создаёт себе задачу из неразмеченных данных (предсказать следующее слово, восстановить замаскированную часть). База pre-training современных LLM. См. [neural-networks/17-self-supervised.md](./neural-networks/17-self-supervised.md).

**Reinforcement learning (RL, обучение с подкреплением)** — агент учится через взаимодействие со средой и награды. Применения: робототехника, игры, RLHF для LLM.

**Inductive bias** — встроенные в модель предположения о структуре данных. Свёртка предполагает локальность, attention — глобальные связи. Без правильного bias модель учится дольше или хуже.

**Generalization (обобщающая способность)** — насколько хорошо модель работает на данных, которых не видела при обучении. Главная цель ML.

**Overfitting (переобучение)** — модель «запомнила» train, плохо работает на test. Симптом: train_loss низкий, val_loss высокий.

**Underfitting (недообучение)** — модель слишком простая, не уловила паттерны. Train и val loss оба плохие.

**Bias-variance tradeoff** — фундаментальный компромисс: слишком простая модель → высокий bias (систематическая ошибка); слишком сложная → высокая variance (зависимость от случайной выборки).

**Curse of dimensionality (проклятие размерности)** — с ростом числа признаков объём пространства растёт экспоненциально, данных «не хватает». kNN ломается первым, деревья страдают меньше.

## 📊 Данные и feature engineering

**Feature (признак)** — входная переменная модели. Например, возраст пользователя, длина текста, RGB-значение пикселя.

**Label / Target (метка / целевая переменная)** — то, что модель предсказывает. «Купит / не купит», «цена», «класс изображения».

**Feature engineering** — создание новых признаков из сырых данных. Часто даёт больший прирост качества, чем смена модели. См. [data-science/08-feature-engineering.md](./data-science/08-feature-engineering.md).

**One-hot encoding** — кодирование категории в вектор из 0 и 1. «Москва» → [1,0,0], «Питер» → [0,1,0]. Простой, но раздувает размерность.

**Target encoding** — замена категории на среднее target по этой категории. Сильный признак, но опасен утечками без правильного CV.

**Embedding** — числовое представление сущности (слова, картинки, пользователя, товара) в виде плотного вектора. Близкие по смыслу сущности — близкие векторы.

**Normalization / Scaling** — приведение признаков к одному масштабу (обычно [0,1] или среднее 0, std 1). Критично для линейных моделей, kNN, нейросетей.

**Data leakage (утечка данных)** — информация из тестовой выборки или будущего попадает в train. Модель показывает завышенное качество, в проде ломается. Самая частая причина «модели, которая работала в ноутбуке».

**Data drift** — распределение входных данных меняется со временем. Модель деградирует, хотя сама не менялась. Лечится мониторингом (PSI, KS-test) и переобучением.

**Concept drift** — связь между признаками и таргетом меняется. Лечится только переобучением на свежих данных.

**Imbalanced data (дисбаланс классов)** — один класс намного редче другого (фрод: 99.9% не-фрод, 0.1% фрод). Accuracy бесполезна, нужны precision/recall, балансировка, веса классов.

**Train / Validation / Test split** — разбиение датасета. Train для обучения, val для подбора гиперпараметров, test — финальная оценка, видим один раз.

**Stratified split** — разбиение с сохранением пропорций классов. Обязательно при дисбалансе.

**Time-based split** — для временных данных: train = прошлое, test = будущее. Random split тут — гарантированная утечка.

**Group split** — когда несколько записей принадлежат одной сущности (пользователю, документу). Все записи одной группы должны быть в одной части split'а.

## 📏 Метрики и валидация

**Accuracy (точность)** — доля правильных предсказаний. Простая, но обманчивая на дисбалансе.

**Precision (точность класса)** — из тех, кого модель назвала позитивным, сколько действительно позитивны. Важна, когда дороже false positive (спам-фильтр: лучше пропустить спам, чем убить важное письмо).

**Recall (полнота)** — из всех реальных позитивных, сколько модель нашла. Важна, когда дороже false negative (медицина: лучше перестраховаться).

**F1-score** — гармоническое среднее precision и recall. Универсальная метрика при дисбалансе.

**ROC-AUC** — площадь под кривой precision-recall при разных порогах. Показывает разделимость классов независимо от порога.

**PR-AUC** — площадь под precision-recall curve. Лучше ROC-AUC при сильном дисбалансе.

**MAE / RMSE / MAPE** — метрики регрессии: средняя абсолютная ошибка, корень из квадратичной, средняя процентная.

**R² (коэффициент детерминации)** — доля дисперсии target, объяснённая моделью. От -∞ до 1.

**Cross-validation (кросс-валидация)** — разбиение данных на K фолдов, обучение K раз, усреднение метрик. Снижает зависимость от случайного split.

**K-Fold CV** — стандартный вариант: K частей, каждая по очереди тест.

**Stratified K-Fold** — K-Fold с сохранением пропорций классов.

**TimeSeriesSplit** — CV для временных рядов: train растёт, test всегда в будущем.

**Nested CV** — двойная вложенная CV: внешний цикл для оценки, внутренний для подбора гиперпараметров. Защищает от утечки гиперпараметров.

**Calibration (калибровка)** — насколько вероятности модели соответствуют реальным частотам. Модель может быть точной, но «слишком уверенной». Лечится Platt scaling или isotonic regression.

**Confusion matrix** — таблица TP/FP/TN/FN. База для всех классификационных метрик.

## 🌲 Алгоритмы классического ML

**Linear Regression (линейная регрессия)** — y = Wx + b. Основа всего: интерпретируема, быстра, понятна.

**Logistic Regression (логистическая регрессия)** — линейная регрессия + сигмоида → классификация. Несмотря на «logistic» в имени — модель классификации.

**Ridge / Lasso / Elastic Net** — линейная регрессия с L2 / L1 / комбинированной регуляризацией. Lasso зануляет малозначимые коэффициенты (feature selection).

**Decision Tree (дерево решений)** — последовательность if-else, выученная по данным. Интерпретируемое, склонно к переобучению.

**Random Forest** — ансамбль деревьев на bagging-подвыборках и случайных подмножествах признаков. Усреднение снижает variance.

**Gradient Boosting** — последовательное обучение слабых моделей, каждая исправляет ошибки предыдущих. Лучший выбор на табличных данных в 2026.

**XGBoost** — оптимизированная реализация gradient boosting. Эталон скорости и качества.

**LightGBM** — бустинг от Microsoft с histogram-based splits. Быстрее XGBoost на больших данных.

**CatBoost** — бустинг от Яндекса с нативной поддержкой категориальных признаков. Меньше нужно feature engineering.

**kNN (k-nearest neighbors)** — предсказание = ответ ближайших соседей в пространстве признаков. Простой, но медленный и страдает от размерности.

**K-Means** — кластеризация: K центроидов, итеративное распределение. Чувствителен к масштабу и начальной инициализации.

**DBSCAN** — кластеризация по плотности. Находит кластеры произвольной формы, выделяет выбросы.

**PCA (principal component analysis)** — линейное снижение размерности через SVD. Сохраняет максимум дисперсии.

**t-SNE / UMAP** — нелинейное снижение размерности для визуализации. UMAP быстрее и лучше сохраняет глобальную структуру.

**SVM (support vector machines)** — поиск гиперплоскости с максимальным зазором. Был популярен до DL, сейчас редко используется на больших данных.

**Naive Bayes** — классификатор на теореме Байеса с предположением независимости признаков. Простой бейзлайн для текста.

## 🧠 Нейросети и Deep Learning

**Neural Network (нейросеть)** — композиция линейных преобразований и нелинейностей. По сути — большая параметризованная функция.

**Neuron (нейрон)** — базовая единица: y = activation(Wx + b).

**Activation function (функция активации)** — нелинейность между слоями. Без неё сеть = одна большая линейная регрессия.

**ReLU** — max(0, x). Стандарт в скрытых слоях. Быстрая, простая, но «умирает» при отрицательных входах.

**GELU** — сглаженный ReLU. Используется в трансформерах. Чуть лучше качество, чуть медленнее.

**Sigmoid** — 1/(1+e^-x). Сжимает в (0,1). В скрытых слоях устарела (vanishing gradients), используется на выходе бинарной классификации.

**Softmax** — превращает вектор в распределение вероятностей. Стандарт на выходе многоклассовой классификации.

**Loss function (функция потерь)** — что минимизируем. MSE для регрессии, cross-entropy для классификации.

**Cross-entropy** — стандартная loss для классификации. Штрафует уверенно-неправильные предсказания сильнее.

**Backpropagation (обратное распространение ошибки)** — алгоритм вычисления градиентов через цепное правило. Сердце обучения нейросетей.

**Gradient Descent (градиентный спуск)** — обновление весов в направлении антиградиента. База всех оптимизаторов.

**SGD (stochastic gradient descent)** — GD по случайному батчу. Шумно, но дешево по памяти.

**Adam / AdamW** — современные оптимизаторы с адаптивным learning rate и моментом. AdamW корректнее обрабатывает weight decay.

**Learning rate (LR)** — размер шага обновления. Главный гиперпараметр. Слишком большой → не сходится; слишком маленький → учится вечно.

**Learning rate schedule** — план изменения LR во время обучения. Warmup + cosine decay — стандарт для трансформеров.

**Warmup** — постепенный рост LR в начале обучения. Стабилизирует обучение трансформеров.

**Batch size** — сколько примеров обрабатываем за один шаг. Влияет на скорость, память, качество.

**Epoch (эпоха)** — один проход по всему датасету.

**Gradient clipping** — обрезка градиентов по норме. Защищает от взрыва градиентов в RNN/трансформерах.

**Vanishing / Exploding gradients** — градиенты затухают или взрываются на глубоких сетях. Решается ReLU, batch norm, residual connections, gradient clipping.

**Dropout** — случайное зануление нейронов во время train. Регуляризация против переобучения.

**Batch Normalization** — нормализация активаций по батчу. Ускоряет обучение CNN.

**Layer Normalization** — нормализация по фичам в одном примере. Используется в трансформерах (batch norm плохо работает с переменной длиной последовательности).

**Weight decay** — L2-регуляризация в нейросетях. Тянет веса к нулю.

**Early stopping** — остановка обучения, когда val loss перестаёт падать. Защита от переобучения.

**Data augmentation** — искусственное расширение датасета через преобразования (поворот, кроп, флип для картинок; синонимы, back-translation для текста).

## 🏗️ Архитектуры и слои

**MLP (multi-layer perceptron)** — полносвязная сеть из нескольких слоёв. Универсальный аппроксиматор, но не учитывает структуру данных.

**CNN (convolutional neural network)** — свёрточная сеть. Использует локальность и инвариантность к сдвигам. Стандарт для изображений до эпохи ViT.

**Convolution (свёртка)** — операция: ядро (фильтр) скользит по входу, на каждой позиции считает скалярное произведение. Детектирует локальные паттерны.

**Pooling** — уменьшение размерности через max или average по окну. Снижает разрешение, повышает инвариантность.

**Stride** — шаг сдвига ядра свёртки.

**Padding** — добавление нулей по краям, чтобы сохранить размер.

**Receptive field** — область входа, влияющая на один выходной нейрон. Растёт с глубиной.

**Residual connection (skip connection)** — добавление входа слоя к его выходу. Решает vanishing gradients, позволяет обучать сети >100 слоёв (ResNet).

**RNN (recurrent neural network)** — обрабатывает последовательность шаг за шагом, передавая hidden state. Страдает от vanishing gradients на длинных последовательностях.

**LSTM (long short-term memory)** — RNN с механизмом gating. Запоминает информацию на длинных дистанциях.

**GRU** — упрощённый LSTM. Меньше параметров, схожее качество.

**Encoder-Decoder** — архитектура «вход → представление → выход». База машинного перевода до трансформеров.

**ResNet** — глубокая CNN с residual connections. Один из самых влиятельных архитектур DL.

**EfficientNet** — семейство CNN с балансированным масштабированием depth/width/resolution.

**ViT (Vision Transformer)** — трансформер для изображений. Картинка режется на патчи и обрабатывается как последовательность токенов.

## 🔄 Трансформеры и attention

**Transformer** — архитектура на self-attention без рекуррентности. Основа всех современных LLM. См. [neural-networks/09-transformer.md](./neural-networks/09-transformer.md).

**Attention** — механизм взвешивания: каждый элемент решает, на какие другие смотреть и насколько сильно.

**Self-attention** — attention внутри одной последовательности: каждый токен смотрит на все остальные (включая себя).

**Query, Key, Value (Q, K, V)** — три проекции входа в attention. Q «спрашивает», K «отвечает на запрос», V — содержимое. Веса = softmax(QK^T / √d).

**Scaled dot-product attention** — формула: Attention(Q,K,V) = softmax(QK^T / √d_k) V. Деление на √d_k стабилизирует градиенты.

**Multi-head attention (MHA)** — параллельные attention-головы с разными Q/K/V проекциями. Позволяют смотреть на разные аспекты.

**MQA (multi-query attention)** — одни K и V на все головы. Экономит память при инференсе ценой небольшого качества.

**GQA (grouped-query attention)** — компромисс между MHA и MQA: группы голов делят K/V. Стандарт в современных LLM (Llama 3, Mistral).

**Positional encoding** — кодирование позиции токена. Без него трансформер инвариантен к перестановкам.

**Sinusoidal positional encoding** — оригинальные синусоидальные функции из «Attention Is All You Need».

**RoPE (Rotary Position Embedding)** — современный стандарт. Кодирует позицию через поворот Q и K. Хорошо экстраполируется на длинные контексты.

**ALiBi** — линейный bias к attention-весам по позициям. Дёшево, хорошо для экстраполяции.

**YaRN** — метод расширения контекстного окна модели через модификацию RoPE.

**Causal mask** — маска, запрещающая attention на будущие токены. Используется в decoder-only моделях (GPT).

**KV-cache** — кеширование Key/Value тензоров между генерациями токенов. Экономит compute в десятки раз при автогенерации.

**FlashAttention** — IO-aware реализация attention. Минимизирует обращения к HBM, в 2-4 раза быстрее наивного softmax(QK^T)V.

**PagedAttention** — управление KV-cache как виртуальной памятью (страницы). Основа vLLM, кратно повышает throughput.

**Encoder-only** — трансформер только из энкодеров (BERT). Хорош для классификации, NER, embedding.

**Decoder-only** — трансформер только из декодеров (GPT). Стандарт для генерации.

**Encoder-Decoder** — оба компонента (T5, BART). Хорош для seq2seq задач (перевод, суммаризация).

**Context window (контекстное окно)** — максимальное количество токенов, которое модель может обработать. 8K, 32K, 128K, 1M+ — растёт с каждым годом.

## 🤖 LLM и обучение языковых моделей

**LLM (Large Language Model)** — большая языковая модель. Технически — трансформер с миллиардами параметров, обученный на огромном корпусе текста.

**Tokenization (токенизация)** — разбиение текста на токены (кусочки). Модель работает не со словами, а с токенами.

**Token** — единица обработки. Обычно 3-4 символа или часть слова. «understanding» → ["under", "stand", "ing"].

**BPE (Byte-Pair Encoding)** — алгоритм построения словаря: итеративно объединяем самые частые пары символов. Используется в GPT.

**WordPiece** — вариант BPE от Google. Используется в BERT.

**SentencePiece** — токенизатор от Google, работает с raw текстом без предварительной разбивки. Используется в Llama, T5.

**tiktoken** — быстрый BPE-токенизатор от OpenAI. Используется в GPT-моделях.

**Vocabulary (словарь)** — множество всех токенов модели. Обычно 30K-200K.

**Pre-training** — обучение модели на огромном корпусе через next-token prediction (или MLM для BERT). Самая дорогая стадия (миллионы $).

**SFT (Supervised Fine-Tuning)** — дообучение на парах «инструкция → ответ». Превращает «модель, читающую интернет» в «модель, отвечающую на вопросы».

**RLHF (Reinforcement Learning from Human Feedback)** — обучение через ранжирование ответов людьми + PPO. Сделало ChatGPT «вежливым».

**Reward model** — модель, предсказывающая, какой ответ предпочёл бы человек. Часть pipeline RLHF.

**PPO (Proximal Policy Optimization)** — алгоритм RL, стандартно используемый в RLHF.

**DPO (Direct Preference Optimization)** — современная замена RLHF. Не требует reward model, обучается напрямую на парах preferred/rejected. Проще, дешевле, часто лучше.

**KTO (Kahneman-Tversky Optimization)** — альтернатива DPO, работающая с бинарными ответами (хороший/плохой) вместо пар.

**GRPO** — групповое расширение PPO, используется в DeepSeek-R1 для reasoning-моделей.

**Constitutional AI (CAI)** — подход Anthropic: вместо human feedback использовать AI feedback, направляемый набором принципов («конституция»).

**RLAIF (RL from AI Feedback)** — RLHF, где фидбек даёт другая модель, а не человек.

**Scaling laws** — эмпирические законы зависимости качества от параметров, данных и compute. Chinchilla показала оптимальное соотношение.

**Chinchilla law** — для оптимального обучения параметров и токенов должно быть примерно поровну (20 токенов на параметр).

**Temperature** — параметр sampling: контролирует «креативность». T=0 — детерминированно, T=1 — стандарт, T>1 — больше случайности.

**Top-k sampling** — выбор из k самых вероятных токенов.

**Top-p (nucleus) sampling** — выбор из минимального набора токенов с суммарной вероятностью ≥ p.

**Greedy decoding** — всегда выбираем самый вероятный токен. Детерминированно, но скучно.

**Beam search** — параллельное держание top-k гипотез. Лучше для машинного перевода, хуже для свободной генерации.

**Speculative decoding** — маленькая модель генерирует черновик, большая верифицирует. Ускоряет инференс в 2-3 раза без потери качества.

**Continuous batching** — динамическое объединение запросов в один батч на уровне токенов. Сердце vLLM.

**Hallucination (галлюцинация)** — LLM уверенно генерирует ложь. Лечится RAG, низкой температурой, eval, structured outputs.

**Sycophancy** — модель подстраивается под мнение собеседника. Побочный эффект RLHF.

**Mode collapse** — модель после RLHF выдаёт однотипные ответы, теряет разнообразие.

## 📚 RAG и retrieval

**RAG (Retrieval-Augmented Generation)** — LLM + поиск по вашим документам. Модель отвечает на основе найденного контекста.

**Chunking** — разбиение документов на куски (chunks) для индексации. От 200 до 2000 токенов, обычно с overlap.

**Overlap** — пересечение соседних чанков. 10-20% — компромисс между полнотой и дубликатами.

**Vector database (векторная БД)** — БД для хранения и поиска embedding-векторов. Qdrant, Weaviate, pgvector, Pinecone, Milvus, Chroma.

**FAISS** — библиотека от Facebook для быстрого поиска ближайших соседей. Лежит под капотом многих vector DB.

**HNSW** — алгоритм приближённого поиска (ANN) на графах. Стандарт в современных vector DB.

**ANN (Approximate Nearest Neighbors)** — приближённый поиск ближайших соседей. Жертвуем точностью ради скорости.

**Cosine similarity** — мера близости векторов: cos(θ) = (a·b) / (|a|·|b|). Стандарт для embeddings.

**Recall@k** — доля релевантных документов в top-k результатов retrieval.

**MRR (Mean Reciprocal Rank)** — средняя обратная позиция первого релевантного документа.

**NDCG (Normalized Discounted Cumulative Gain)** — метрика ранжирования с учётом позиции и градации релевантности.

**BM25** — классический алгоритм keyword search. Хорош для редких слов, плохо ловит синонимы.

**Hybrid search** — комбинация vector search и BM25. Часто +20% качества vs только vector.

**RRF (Reciprocal Rank Fusion)** — простой способ слить ранжирования из разных источников по обратным рангам.

**Reranking** — второй проход более точной (но медленной) моделью поверх top-k. Cross-encoder обычно даёт +15-25% к качеству.

**Cross-encoder** — модель, кодирующая пару (query, doc) совместно. Точнее bi-encoder, но медленнее.

**Bi-encoder** — query и doc кодируются отдельно. Быстрее, можно индексировать. Используется для retrieval.

**HyDE (Hypothetical Document Embeddings)** — LLM генерирует «идеальный ответ», его embedding используется для поиска. Улучшает retrieval на вопросах.

**Query rewriting** — переформулировка запроса LLM перед поиском. Помогает с короткими/неясными запросами.

**Multi-hop retrieval** — поиск в несколько шагов: ответ на промежуточный вопрос используется для следующего запроса.

**RAGAS** — фреймворк eval для RAG: faithfulness, answer relevancy, context precision/recall.

**Self-RAG** — модель сама решает, когда retrieval нужен, а когда нет.

## 🛠️ Агенты и tool use

**Agent (AI-агент)** — LLM в цикле «думаю → действую → наблюдаю». С доступом к инструментам и памятью.

**Tool use / function calling** — LLM возвращает JSON с вызовом функции. Хост-приложение исполняет и возвращает результат.

**ReAct (Reason + Act)** — паттерн: модель чередует рассуждения (Thought) и действия (Action). Простой и часто эффективный.

**Toolformer** — самообучение LLM использованию инструментов.

**Reflexion** — агент анализирует свои ошибки и хранит «уроки» в памяти.

**Chain-of-Thought (CoT)** — модель пишет цепочку рассуждений перед ответом. Резко улучшает математику и логику.

**Tree of Thoughts (ToT)** — параллельное исследование нескольких цепочек рассуждений с откатом.

**MCP (Model Context Protocol)** — стандарт от Anthropic для подключения инструментов и контекста к LLM. Уже поддержан OpenAI, Cursor, многими IDE.

**LangChain** — фреймворк для построения LLM-приложений. Цепочки, агенты, retrieval.

**LangGraph** — фреймворк state machines для агентов от тех же авторов. Более гибкий, чем LangChain.

**LlamaIndex** — фреймворк, заточенный под RAG.

**DSPy** — фреймворк, где промпты компилируются и автоматически оптимизируются.

**Multi-agent system** — несколько LLM работают вместе. Часто overkill, но иногда оправдано (research, debate).

**CrewAI / AutoGen** — фреймворки для мульти-агентных систем.

**Computer Use** — агент управляет компьютером через скриншоты и эмуляцию ввода. Claude Computer Use, OpenAI Operator.

**Browser agent** — агент, работающий с браузером. Browser Use, Playwright + LLM.

## 🎨 Generative AI и мультимодальность

**Generative AI** — модели, генерирующие новый контент (текст, картинки, видео, аудио).

**Diffusion model** — модель, генерирующая через постепенное «удаление шума» из случайного начального тензора. База Stable Diffusion. См. [neural-networks/14-diffusion.md](./neural-networks/14-diffusion.md).

**DDPM (Denoising Diffusion Probabilistic Models)** — оригинальная статья о диффузионных моделях.

**DDIM** — ускоренный sampling для diffusion (10-50 шагов вместо 1000).

**Latent Diffusion** — диффузия в латентном пространстве VAE. Основа Stable Diffusion: дёшево по compute.

**Flow Matching / Rectified Flow** — современная альтернатива диффузии. Используется в Flux, Stable Diffusion 3.

**DiT (Diffusion Transformer)** — диффузия на трансформере вместо U-Net. Используется в Sora.

**Classifier-Free Guidance (CFG)** — техника усиления влияния промпта на генерацию. Параметр guidance scale.

**ControlNet** — добавление структурного контроля к диффузии (поза, контур, depth map).

**IP-Adapter** — image prompt: используем картинку как промпт.

**VLM (Vision-Language Model)** — модель, работающая с текстом и изображениями. CLIP, BLIP, LLaVA, Qwen-VL.

**CLIP** — модель, обучающая совместное embedding пространство для текста и картинок. База для retrieval и условной генерации.

**LLaVA** — open-source VLM: vision encoder + projector + LLM.

**Whisper** — open-source модель ASR от OpenAI. Поддерживает 100+ языков.

**TTS (Text-to-Speech)** — синтез речи. ElevenLabs, OpenAI TTS, Coqui.

**Voice cloning** — клонирование голоса по короткому сэмплу.

## 🔧 Fine-tuning и эффективность

**Fine-tuning (дообучение)** — продолжение обучения предобученной модели на новых данных.

**Full fine-tuning** — обновляем все параметры. Дорого, требует много памяти.

**PEFT (Parameter-Efficient Fine-Tuning)** — обучаем малую долю параметров. LoRA, prefix tuning, adapters.

**LoRA (Low-Rank Adaptation)** — добавляем низкоранговые «адаптеры» к весам. Обучаем только их. Экономит память в десятки раз.

**QLoRA** — LoRA на квантованной (4-bit) модели. Позволяет fine-tune 70B модель на одной GPU 24GB.

**Adapters** — маленькие модули между слоями. Альтернатива LoRA.

**Prefix tuning** — обучение «виртуальных токенов» в начале входа.

**Prompt tuning** — обучение embeddings промпта без изменения модели.

**Quantization (квантование)** — переход с fp32/fp16 на int8/int4. Сжимает модель в 2-8 раз.

**PTQ (Post-Training Quantization)** — квантуем после обучения. Просто, иногда теряем качество.

**QAT (Quantization-Aware Training)** — учитываем квантование при обучении. Качественнее, дороже.

**GPTQ / AWQ** — методы 4-bit квантования для LLM. Сохраняют большую часть качества.

**GGUF** — формат квантованных моделей для llama.cpp. Удобен для CPU и Apple Silicon.

**Bitsandbytes** — библиотека для 8/4-bit квантования в PyTorch.

**Knowledge distillation** — обучение маленькой модели «студента» предсказаниям большой «учителя».

**Pruning** — удаление маловажных параметров. Sparsity ускоряет на специальном железе.

**MoE (Mixture of Experts)** — для каждого токена активируется только подмножество «экспертов». Mixtral, DeepSeek.

**Speculative decoding** — см. в разделе LLM.

**Continuous batching** — см. в разделе LLM.

**Monitoring** — отслеживание здоровья модели: качество, latency, ошибки, дрейф.

**PSI (Population Stability Index)** — метрика для детекции дрейфа распределений.

**KS-test** — статистический тест Колмогорова-Смирнова для сравнения распределений.

**Evidently AI** — opensource библиотека для мониторинга ML.

**Retraining strategy** — план переобучения: по расписанию / триггеру / деградации метрик.

**SLA / SLO / SLI** — соглашения об уровне сервиса: целевые показатели и измерения.

**Observability** — возможность понять, что происходит внутри системы по логам, метрикам, трейсам.

**OpenTelemetry** — стандарт для трейсинга и метрик.

**Distributed tracing** — отслеживание запроса через цепочку микросервисов.

## 📈 A/B-тесты и causal inference

**A/B-тест** — рандомизированное сравнение двух (или более) вариантов. Золотой стандарт для оценки изменений.

**Control group / Treatment group** — контрольная и тестовая группы.

**Hypothesis (гипотеза)** — H0 (нулевая) vs H1 (альтернативная). Тестируем, отвергаем ли H0.

**p-value** — вероятность наблюдать данные (или более экстремальные) при истинности H0. Маленький p → отвергаем H0.

**Statistical significance** — статистическая значимость. Обычно порог p < 0.05.

**Type I error (ошибка первого рода)** — false positive: «нашли эффект, которого нет». Контролируется уровнем α.

**Type II error (ошибка второго рода)** — false negative: «не нашли эффект, который есть». Контролируется мощностью.

**Power (мощность теста)** — 1 - β. Вероятность найти эффект при его наличии. Обычно целятся в 80%.

**MDE (Minimum Detectable Effect)** — минимальный эффект, который тест может обнаружить с заданной мощностью.

**Sample size calculation** — расчёт необходимого размера выборки.

**Confidence interval (доверительный интервал)** — диапазон, который с вероятностью X% содержит истинное значение.

**Bootstrap** — оценка распределения через resampling с возвращением.

**SRM (Sample Ratio Mismatch)** — расхождение фактического разбиения с ожидаемым. Признак бага в системе сплитования.

**Multiple testing problem** — при тестировании множества гипотез растёт вероятность ложного срабатывания. Лечится поправками Bonferroni / Benjamini-Hochberg.

**CUPED** — техника снижения variance в A/B-тестах через коваты (например, pre-period метрика).

**Novelty effect** — временный эффект от новизны изменения. Искажает результаты первой недели.

**Causal inference** — выявление причинно-следственных связей из данных.

**Confounding (искажающие факторы)** — переменные, влияющие и на лечение, и на исход. Создают ложные корреляции.

**Propensity score matching** — подбор пар объектов из treatment и control с похожими характеристиками.

**Difference-in-Differences (DiD)** — сравнение изменений в treatment и control группах до и после.

**Instrumental variables** — переменные, влияющие на исход только через лечение. Помогают при confounding.

**Uplift modeling** — моделирование индивидуального эффекта лечения. «Кому именно поможет?»

## 🛡️ Безопасность LLM

**Prompt injection** — атака, при которой пользователь внедряет инструкции в промпт, обходя системные правила.

**Indirect prompt injection** — инъекция через сторонние источники (документы, веб-страницы, email), которые модель читает.

**Jailbreak** — обход safety-фильтров модели через хитрые промпты.

**DAN (Do Anything Now)** — классический jailbreak-промпт.

**GCG (Greedy Coordinate Gradient)** — автоматическая атака на LLM через градиентную оптимизацию.

**Many-shot jailbreak** — атака через множество примеров в длинном контексте.

**Data exfiltration** — извлечение конфиденциальных данных из модели через хитрые запросы.

**PII leakage** — утечка персональных данных (имена, телефоны, email).

**Model stealing** — реконструкция модели через массовые запросы.

**Membership inference** — определение, был ли конкретный пример в train.

**Guardrails** — фильтры на входе/выходе LLM. NeMo Guardrails, Guardrails AI, Llama Guard.

**Red-teaming** — намеренные атаки на свою систему для поиска уязвимостей.

**OWASP Top-10 for LLM** — каталог типовых уязвимостей LLM-приложений.

**Constitutional AI** — см. выше, подход Anthropic к alignment через принципы.

**Sandboxing** — запуск инструментов агента в изолированной среде.

**Rate limiting** — ограничение частоты запросов для защиты от злоупотреблений.

**Content filtering** — фильтрация неподобающего контента на входе/выходе.

**Machine Learning Engineer (MLE)** — пайплайны, инференс, latency, надёжность. Ближе к backend.

**MLOps / Platform Engineer** — инфраструктура для ML-команды. Kubernetes, observability, CI/CD моделей.

**Research Engineer** — реализация статей, эксперименты с архитектурами. Мост между research и prod.

**Research Scientist** — свои статьи, PhD-уровень. Топовые лабы: Anthropic, OpenAI, DeepMind, Meta FAIR.

**LLM / GenAI Engineer** — новая роль. Промпты, RAG, агенты, fine-tuning. Самая горячая в 2024-2026.

**Applied AI Engineer** — встраивание AI-фич в продукт. Гибрид product + ML + backend.

**AI Safety Researcher** — red-teaming, evaluation, interpretability.

**Data Engineer (DE)** — пайплайны данных, DWH, ETL. Без них ML невозможен.

**Analytics Engineer** — мост между DE и DS: моделирование данных, dbt, метрики.

**T-shape** — широкие знания + одна глубокая специализация. Стандартный паттерн для сениоров.

**Tech Lead** — технический лидер команды. Не обязательно менеджер.

**Staff Engineer** — уровень выше сениора. Архитектура, влияние на несколько команд.

**Principal Engineer** — top tier IC (Individual Contributor) трек. Влияние на компанию/индустрию.

**IC track / Manager track** — две карьерные траектории: индивидуальный контрибьютор vs менеджер.
