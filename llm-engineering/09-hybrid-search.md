# 09. Hybrid search: BM25 + векторы + reranking

Чистый векторный поиск плохо работает на запросах с конкретными терминами, кодами, артикулами, именами. Полнотекстовый — на парафразах. Их объединение почти всегда даёт лучшее качество, чем любой из них в отдельности.

## Почему чистых векторов мало

Эмбеддинги хорошо ловят смысловую близость, но плохо — точные совпадения. Запрос "ошибка ERR-4042" и документ "ошибка ERR-4042 описана здесь" по векторам могут оказаться дальше друг от друга, чем "ошибка системы" и "сбой в сервисе". BM25 такие совпадения находит мгновенно.

## BM25

Классическая TF-IDF-подобная метрика с насыщением частоты. Работает на инвертированном индексе. Реализации:
- `rank_bm25` (Python, in-memory).
- Elasticsearch / OpenSearch.
- Postgres full-text search.
- BM25 в Qdrant / Weaviate.

## Объединение результатов

### Reciprocal Rank Fusion (RRF)

Самый простой и удивительно сильный метод:
```
score(d) = sum over rankers: 1 / (k + rank_i(d))
```
`k = 60` — стандарт. Не требует калибровки скор'ов.

### Linear combination

```
score(d) = α × vector_score + (1 − α) × bm25_score
```
Требует нормализации скор'ов. `α` подбирается на валидационной выборке.

## Reranking

После получения top-50 кандидатов с обоих сторон, проходим cross-encoder'ом (например, `bge-reranker-v2-m3` или Cohere Rerank API). Cross-encoder смотрит на пару (запрос, документ) и выдаёт точный score. Дорого, но качество top-K взлетает.

```python
def retrieve(query, k=5):
    vec = vector_search(query, k=30)
    bm = bm25_search(query, k=30)
    candidates = rrf_fuse([vec, bm])[:50]
    return reranker.rerank(query, candidates)[:k]
```

## Когда что использовать

- Только векторы — если запросы и документы разной формы (длинные документы, короткие запросы).
- Только BM25 — если запросы и документы используют одну терминологию (документация, юр.тексты).
- Hybrid + reranking — почти всегда лучший вариант для прода.

## Антипаттерны

- Линейная комбинация без нормализации скор'ов. BM25-score и cosine — в разных шкалах.
- Reranking без замера — может не дать пользы на ваших данных.
- Hybrid из 3+ ретриверов "потому что круче". Усложнение, которое не окупается.
- Хардкодить `α` в коде. Сделайте параметром, валидируйте на тестах.

## Практика

1. Постройте BM25 индекс на ваших документах (`rank_bm25` или Qdrant). Замерьте Recall@5.
2. Постройте векторный индекс. Замерьте Recall@5 на тех же запросах.
3. Найдите запросы, где побеждает только один из подходов. Поймите паттерн.
4. Реализуйте RRF-фьюзер. Замерьте качество.
5. Добавьте reranking (Cohere Rerank или локальный bge-reranker). Сравните top-3 до и после.
6. Замерьте latency каждого этапа. Найдите узкое место.
