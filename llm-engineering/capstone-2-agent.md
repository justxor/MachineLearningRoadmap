# Капстон 2. Агент для автоматизации рабочих задач

Постройте агента, который выполняет последовательность реальных действий через инструменты. Цель — научиться делать НАДЁЖНЫХ агентов, которые не делают глупостей, не зацикливаются и не разоряют пользователя.

## Идеи задач (выбрать одну)

- **DevOps-ассистент**: получает алёрт → собирает логи через инструменты → диагностирует → предлагает фикс или открывает тикет в Jira.
- **Email-помощник**: читает входящие → классифицирует → черновики ответов на типовые → ожидание подтверждения → отправка.
- **Аналитик данных**: на естественном языке запрос → SQL → выполнение в БД → визуализация → текстовый вывод.
- **Code reviewer**: получает diff → анализирует → оставляет комментарии в PR через GitHub API.

## Требования

### Функциональные

1. ≥ 4 инструмента с понятными описаниями.
2. ReAct-цикл с trace каждого шага.
3. Подтверждение для деструктивных операций.
4. Память между сессиями (БД или vector store).
5. Веб-UI или CLI с показом trace пользователю.

### Нефункциональные

1. max_steps, max_cost, max_duration.
2. Same-action detector (защита от зацикливания).
3. Логирование всех вызовов tools.
4. Eval-датасет с задачами разной сложности.
5. Тесты на безопасность: prompt injection через данные tools.

## Архитектура

```
[User Query] → [Agent Loop]
                    ↓
            [LLM with tools]
                    ↓
       ┌──────┬─────┴─────┬──────┐
   [Tool A][Tool B]    [Tool C][Tool D]
       └──────┴────┬──────┴──────┘
                   ↓
            [Trace storage]
                   ↓
            [Memory store]
                   ↓
            [Final answer]
```

Под капотом: LangGraph или собственная state machine. Checkpointer в PostgreSQL.

## Этапы

1. **Неделя 1.** 4 tools, минимальный ReAct, CLI.
2. **Неделя 2.** Лимиты, обработка ошибок, human-in-the-loop на деструктивных операциях.
3. **Неделя 3.** Память между сессиями, веб-UI.
4. **Неделя 4.** Evals, тесты на безопасность, мониторинг.
5. **Неделя 5.** Полировка, документация, релиз.

## Метрики приёмки

- Success rate на eval-сценариях ≥ 0.80.
- Средняя длина trace в шагах ≤ 8.
- 0 случаев зацикливания на 100 запусках.
- Деструктивные операции всегда требуют подтверждения.
- 0 успешных prompt injection из подготовленных тест-кейсов.

## Что положить в резюме

- "Production-ready агент с 6 инструментами и safety-проверками. Success rate 0.83 на 120 сценариях, 0 случаев утечки данных через indirect prompt injection."
- Демо-видео работы агента.
- Ссылка на репозиторий с подробным README.

## Распространённые ловушки

- Агент уходит в цикл — забыли same-action detector.
- Большие счета за токены — забыли max_cost на сессию.
- Tool возвращает огромный JSON, контекст переполняется — суммаризируйте или фильтруйте перед возвратом.
- Памятью назвали json-файл — на нагрузке потеряется. Берите БД сразу.
