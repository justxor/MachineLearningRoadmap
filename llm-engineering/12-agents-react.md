# 12. ReAct, планирование, многошаговые задачи

Когда задача требует нескольких действий, не помещающихся в один вызов LLM, мы переходим от "вопрос-ответ" к агенту. Агент — это цикл, в котором LLM решает, что делать дальше, выполняет действие через tools и смотрит на результат.

## ReAct

ReAct = Reasoning + Acting. На каждом шаге модель выдаёт:
- **Thought**: что я думаю / планирую.
- **Action**: какой tool вызвать.
- **Observation**: результат tool'а (вы подставляете).

Повторяется до тех пор, пока модель не выдаст финальный ответ. Прозрачно, дебажится, легко аудируется.

```
Thought: Чтобы ответить, нужно знать курс доллара. Вызову get_rate.
Action: get_rate(currency="USD")
Observation: 92.5
Thought: Курс получен. Теперь могу ответить.
Final: Курс USD сегодня — 92.5 руб.
```

## Структура агентного цикла

```python
def run_agent(query: str, tools: list, max_steps: int = 10):
    messages = [{"role": "user", "content": query}]
    for step in range(max_steps):
        response = llm.complete(messages, tools=tools)
        if not response.tool_calls:
            return response.text
        for call in response.tool_calls:
            result = execute(call.name, call.args)
            messages.append({"role": "tool", "tool_call_id": call.id, "content": result})
        messages.append(response)
    raise AgentTimeout(f"Did not converge in {max_steps} steps")
```

## Жёсткие ограничения

Без них агенты уходят в бесконечный цикл, тратят токены и нервы:

- **max_steps**: жёсткий лимит итераций (5–15 в большинстве задач).
- **max_cost**: лимит в долларах на сессию.
- **max_duration**: лимит по времени.
- **same-action detector**: если последние 3 шага одинаковые — стоп.

## Планирование

Для сложных задач полезен предварительный план. Модель сначала строит план (список шагов), потом выполняет. План можно показать пользователю на одобрение.

Plan-and-execute против ReAct: план меньше тратит токенов, но хуже адаптируется к ошибкам. ReAct гибче, но дороже. Гибрид (план + ReAct внутри шагов) — часто лучший вариант.

## Память агента

В рамках одной сессии — история сообщений. Между сессиями — внешнее хранилище (БД, vector store). Не пытайтесь "запомнить всё в промпте" — расти будет бесконечно.

## Антипаттерны

- Агент без max_steps. Готовьтесь к счетам за токены.
- Агент-универсал на 30 инструментов "на все случаи жизни". Лучше специализированные агенты.
- Прятать от пользователя, что вызывалось. При баге не разберётесь.
- Делать агентом то, что решается одним вызовом LLM + tools.

## Практика

1. Реализуйте минимальный ReAct-цикл с 3 tools. Покажите trace каждого шага.
2. Возьмите задачу "найди X, посчитай Y, отправь Z" и пройдите её агентом.
3. Добавьте max_steps, max_cost, same-action detector. Спровоцируйте срабатывание каждого.
4. Реализуйте plan-and-execute: сначала план, потом исполнение. Сравните с чистым ReAct по стоимости и качеству.
5. Сохраните trace выполнения в JSON. Сделайте утилиту для его визуализации.
6. Найдите 5 задач, для которых агент НЕ нужен (хватает одного вызова). Зафиксируйте критерий "когда агент".

## Чек-лист

- [ ] У каждого агента есть max_steps и max_cost.
- [ ] Trace выполнения сохраняется и доступен для отладки.
- [ ] Есть детектор зацикливания.
- [ ] Понимаю, когда агент оправдан, а когда — оверкилл.
- [ ] Память между сессиями вынесена во внешнее хранилище.
