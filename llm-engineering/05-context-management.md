# 05. Управление контекстом и токенами

Контекстное окно — это не "положи всё, что есть". Это бюджет, которым нужно распоряжаться. Большие модели дороже, длинные контексты замедляют ответ и теряют информацию в середине. Управление контекстом — главное отличие игрушки от продукта.

## Бюджет контекста

Каждый вызов: `tokens_in × price_in + tokens_out × price_out`. На большом траффике 10k токенов лишнего контекста = тысячи долларов в месяц.

Считайте бюджет заранее:
- Системный промпт: 200–500 токенов.
- Few-shot: 500–2000 токенов.
- Контекст (RAG-чанки, история): X токенов.
- Запрос пользователя: 100–500 токенов.
- Резерв на ответ: 500–2000 токенов.

Если суммарно > 8k и вы используете не флагман — пересмотрите архитектуру.

## История диалога

Три стратегии:

1. **Окно**: храним последние N сообщений. Просто, но теряем контекст.
2. **Суммаризация**: старые сообщения суммируем в одно. Дешевле, но теряем детали.
3. **Hybrid**: суммаризация + последние K реплик целиком. Лучший компромисс.

```python
def trim_history(messages, max_tokens=4000):
    if count_tokens(messages) <= max_tokens:
        return messages
    summary = summarize(messages[:-5])
    return [{"role": "system", "content": f"Резюме: {summary}"}] + messages[-5:]
```

## Prompt caching

Anthropic и OpenAI поддерживают кэширование префикса промпта. Если у вас стабильный системный промпт + большой набор инструкций + меняющийся пользовательский запрос — кэшируйте стабильную часть. Экономия до 10× по входным токенам.

```python
messages = [
    {"role": "system", "content": [
        {"type": "text", "text": HUGE_INSTRUCTIONS, "cache_control": {"type": "ephemeral"}}
    ]},
    {"role": "user", "content": user_query}
]
```

## Lost-in-the-middle

Эксперименты показывают: модели хуже используют информацию из середины длинного контекста. Самое важное помещайте в начало или в конец. Не надейтесь, что модель найдёт нужную фразу в 50k токенов.

## Сжатие контекста

Если на вход приходит 30k токенов документации, а вопрос конкретный — лучше сначала отретривить релевантные куски (RAG), чем тащить всё. Контекстное окно — не замена поиску.

## Антипаттерны

- "У Gemini 2M контекст, давайте сольём туда всю базу знаний". Дорого, медленно, точность падает.
- Хранить всю историю диалога без обрезки. Через 100 сообщений вы платите за каждое заново.
- Не считать токены при отладке. "Что-то медленно работает" — это обычно раздувшийся контекст.
- Не использовать prompt caching при стабильных префиксах.

## Практика

1. Возьмите свой типичный вызов. Замерьте токены каждой секции: system, examples, context, query. Найдите, что можно сократить.
2. Реализуйте `trim_history` с тремя стратегиями (window, summary, hybrid). Сравните на чате из 50 реплик.
3. Внедрите prompt caching для большого системного промпта. Замерьте экономию в долларах.
4. Сделайте тест на lost-in-the-middle: спрячьте факт в начале, середине и конце 30k-токенного контекста. Замерьте accuracy.
5. Напишите утилиту `token_budget(model)`, которая раскладывает доступный бюджет на секции и предупреждает при превышении.
6. Возьмите промпт длиной 5000 токенов и сократите до 2000 без потери качества (с прогоном тестов).
