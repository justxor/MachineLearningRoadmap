# 22. Локальный инференс: llama.cpp, vLLM, Ollama

Локальный инференс — это не "круто и приватно", это инженерный компромисс с цифрами на руках. Этот урок про то, когда он реально окупается, и как его запустить, чтобы не превратиться в эксплуатационника GPU 24/7.

## Когда брать локальный инференс

- Жёсткие требования по приватности (медицина, банки, гос).
- Очень большой объём (десятки–сотни миллионов токенов в месяц), когда API становится дорогим.
- Нужен контроль над моделью (fine-tuned версия, специфическое поведение).
- Регуляторные требования (данные не покидают периметр).

## Когда НЕ брать

- Меньше 10M токенов в месяц — облако дешевле.
- Нет инженеров с опытом эксплуатации GPU.
- Нужна максимальная мощность (флагманские модели всё ещё в облаке).
- Постоянно разные пиковые нагрузки — облако эластичнее.

## Стек

### Ollama

Самый простой способ. `ollama run llama3.1:8b`. Хороша для разработки, прототипов, малых нагрузок. Не для прода с высокой нагрузкой.

### llama.cpp

C++-сервер для GGUF-моделей. Работает на CPU и GPU, на маках через Metal. Эффективный, но требует ручной настройки.

### vLLM

Прод-движок. PagedAttention, continuous batching, OpenAI-совместимый API. Высокая пропускная способность. Использует CUDA, нужен NVIDIA GPU.

### Альтернативы

- **TGI** (HuggingFace Text Generation Inference).
- **SGLang** — новый движок, конкурирует с vLLM.
- **MLC-LLM** — для edge и мобильных.

## Выбор модели

| Размер | VRAM (Q4) | Применение |
|---|---|---|
| 7–8B | 4–6 ГБ | Классификация, простой RAG |
| 13–14B | 8–10 ГБ | Сложнее RAG, агенты |
| 32–34B | 20+ ГБ | Качество, близкое к слабым облачным |
| 70B+ | 40+ ГБ или multi-GPU | Серьёзный прод |

Семейства: Llama 3.1/3.3, Qwen 2.5, DeepSeek, Mistral, Gemma.

## Квантование

Понижение точности весов: FP16 → Q8 → Q5 → Q4 → Q3. Уменьшает VRAM и ускоряет, но снижает качество. Q4 — обычный компромисс.

Замеряйте качество на ваших задачах после квантования. Иногда падение ничтожно, иногда катастрофично.

## Развёртывание

```bash
# vLLM
docker run --gpus all -p 8000:8000 \
  vllm/vllm-openai \
  --model meta-llama/Llama-3.1-8B-Instruct \
  --max-model-len 8192
```

Совместимый с OpenAI API — ваш существующий клиент работает без изменений (поменяйте base_url).

## Мониторинг

- GPU utilization, VRAM usage.
- TPS, TTFT, queue length.
- OOM, restart count.
- Стандартные APM (Prometheus + Grafana).

GPU за $30k не должен простаивать на 5%.

## Антипаттерны

- "Поставим Ollama в Kubernetes". В проде нужен vLLM или TGI.
- Не замерять качество после квантования.
- Один GPU без отказоустойчивости. Под нагрузкой ляжет — и сервис упадёт.
- Считать, что локальный = бесплатный. GPU стоят денег: капекс или аренда.
- Игнорировать обновления моделей. Через полгода ваш Llama 3.1 уступает Llama 4.

## Практика

1. Поставьте Ollama и Llama 3.1 8B. Прогоните ваш типичный промпт. Сравните с GPT-4o-mini.
2. Запустите vLLM в Docker. Замерьте TPS на batch size 1, 4, 16.
3. Возьмите модель в Q8, Q5, Q4. Прогоните eval. Постройте график "качество × размер".
4. Реализуйте OpenAI-compatible клиент, который работает с локальным сервером без изменений.
5. Посчитайте unit economics: стоимость GPU в час / число обработанных запросов = стоимость на запрос. Сравните с облаком.
6. Подключите Prometheus к vLLM. Постройте dashboard.
