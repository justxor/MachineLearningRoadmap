# 14. MCP (Model Context Protocol) и подключение внешних систем

MCP — это открытый протокол от Anthropic для стандартного подключения LLM-приложений к внешним источникам данных и инструментам. Идея простая: вместо того чтобы для каждой связки клиент×сервер писать кастомный код, есть общий интерфейс — как USB для периферии.

## Зачем нужен MCP

До MCP каждое LLM-приложение писало свою интеграцию с каждым сервисом. С MCP:
- Сервер (например, Postgres, Jira, GitHub, ваша внутренняя CRM) реализует MCP-протокол один раз.
- Любой MCP-клиент (Claude Desktop, ваш агент, IDE) подключается без новой интеграции.
- Появляется экосистема готовых серверов.

## Из чего состоит MCP

- **Resources**: данные, которые сервер отдаёт по запросу (документы, записи БД, файлы).
- **Tools**: функции, которые сервер умеет выполнять (как в function calling).
- **Prompts**: предзаготовленные шаблоны промптов от сервера.
- **Sampling**: сервер может попросить клиента выполнить LLM-вызов.

Транспорт: stdio (для локальных), HTTP/SSE (для удалённых).

## Пример подключения

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-filesystem", "/home/user/docs"]
    },
    "postgres": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-postgres", "postgres://..."]
    }
  }
}
```

После такой конфигурации ваш агент видит и tools, и resources обоих серверов.

## Когда писать свой MCP-сервер

- У вас есть внутренний API/БД, к которому хочется давать доступ нескольким LLM-приложениям.
- Хочется отделить логику доступа к данным от логики агента.
- Нужна возможность переиспользовать интеграцию.

Если у вас единственное приложение — голый function calling проще.

## Безопасность

MCP-сервер часто имеет доступ к чувствительным данным (БД, файлы, API). Подходите как к любому сервису:
- Аутентификация при подключении.
- Минимально необходимые права (read-only по умолчанию).
- Аудит всех вызовов.
- Whitelist разрешённых tools для конкретного клиента.

## Антипаттерны

- "Поставим MCP-сервер от васи-с-гитхаба с rw-доступом ко всему". Это путь к утечкам и порче данных.
- Превращать всё в MCP, включая внутренние функции. Лишние накладные расходы.
- Не логировать вызовы MCP-tools. Не разберётесь, что агент сделал с БД.
- Полагаться на MCP-сервер без таймаутов и rate-limit'ов.

## Практика

1. Поставьте Claude Desktop и подключите готовый MCP-сервер (например, filesystem). Поэкспериментируйте.
2. Возьмите спецификацию MCP с modelcontextprotocol.io. Напишите простой сервер с одним tool (например, "получить курс валюты").
3. Подключите свой сервер к Claude Desktop или своему агенту. Убедитесь, что tool виден.
4. Добавьте resource: список файлов в директории. Проверьте, что клиент его видит.
5. Сделайте сервер с двумя режимами: read-only и admin. Реализуйте проверку токена.
6. Напишите свой минимальный MCP-клиент на Python, который умеет вызывать tool у внешнего сервера.
