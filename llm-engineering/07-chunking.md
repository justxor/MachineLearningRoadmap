# 07. Чанкование и предобработка документов

Качество RAG на 50% определяется качеством чанков. Плохо нарезали — модель никогда не найдёт ответ, даже если он в данных. Это самый недооценённый этап.

## Принципы хорошего чанка

- **Атомарность**: один чанк ≈ одна мысль/факт.
- **Самодостаточность**: чанк понятен вне контекста документа.
- **Размер 200–800 токенов**: меньше — мало контекста, больше — шум.
- **Overlap 10–20%**: чтобы факт на границе не потерялся.

## Стратегии чанкования

### Fixed-size

Разрезать каждые N токенов. Быстро и тупо. Подходит для однородных данных (логи, чаты). Ломается на структурированных документах (разрезает таблицы и заголовки).

### Recursive character splitting

Идём по иерархии разделителей: `\n\n` → `\n` → `. ` → пробел. Стандарт LangChain. Хороший дефолт для текста.

### Semantic chunking

Считаем эмбеддинги предложений, склеиваем соседние, пока косинусное сходство выше порога. Границы — где смысл меняется. Дороже, но качество выше на сложных документах.

### Document-structure aware

Используем структуру документа: разрезы по заголовкам, секциям, главам. Каждый чанк сохраняет путь `H1 > H2 > H3`. Идеально для документации, юридических текстов, технических спецификаций.

## Предобработка

- **PDF**: используйте `unstructured`, `pymupdf`, `pdfplumber`. Извлекайте таблицы отдельно.
- **HTML**: удалите nav, footer, рекламу. `readability-lxml` или `trafilatura`.
- **Office**: `python-docx`, `openpyxl`. Таблицы — в markdown.
- **OCR**: `tesseract`, `paddleocr` для сканов.

Грязные данные → грязный индекс → бесполезный RAG.

## Метаданные

Каждый чанк — это не только текст. Сохраняйте:
- ID документа, путь, дата обновления.
- Заголовок секции, иерархия.
- Тип контента (текст / код / таблица).
- Права доступа (для filter'ов при поиске).

```python
@dataclass
class Chunk:
    text: str
    doc_id: str
    section_path: list[str]
    page: int
    chunk_type: Literal["text", "code", "table"]
    permissions: list[str]
```

## Антипаттерны

- Чанковать по 1000 символов "потому что у LangChain так в туториале".
- Игнорировать структуру документа.
- Терять метаданные при чанковании.
- Хранить таблицы как обычный текст. Преобразуйте в markdown или JSON.
- Не переиндексировать при изменении стратегии чанкования.

## Практика

1. Возьмите 10 документов разных типов (PDF, markdown, HTML). Прогоните через 3 стратегии чанкования.
2. Сделайте 20 вопросов, ответы на которые лежат в этих документах. Замерьте Recall@5 для каждой стратегии.
3. Извлеките таблицы из PDF и преобразуйте в markdown. Сравните retrieval с таблицей как текстом и как markdown.
4. Реализуйте document-structure-aware chunking для markdown с сохранением иерархии заголовков.
5. Реализуйте semantic chunking. Сравните стоимость и качество с recursive.
6. Сделайте утилиту, которая показывает: какой документ, какие чанки, размер каждого, метаданные.

## Чек-лист

- [ ] Знаю размер своих чанков в токенах, не в символах.
- [ ] Сохраняю метаданные и структуру при чанковании.
- [ ] Таблицы и код обрабатываются отдельно от текста.
- [ ] Есть тест на retrieval, который ловит регрессии при смене чанкования.
- [ ] Стратегия выбрана по замерам, а не по моде.
