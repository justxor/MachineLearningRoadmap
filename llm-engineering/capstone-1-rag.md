# Капстон 1. RAG-ассистент на корпоративных документах

Постройте сервис, который отвечает на вопросы по набору документов (например, документация продукта, юридические тексты, внутренние wiki). Уровень — production-ready, с метриками, мониторингом и evals.

## Постановка

- Вход: вопрос пользователя на естественном языке (русский / английский).
- Выход: ответ + список источников (документ + страница / секция).
- SLA: p95 latency < 5 сек, accuracy ≥ 0.85 на eval-датасете.
- Бюджет: ≤ $X на 1000 запросов (определите сами).

## Требования

### Функциональные

1. Загрузчик документов: PDF, markdown, HTML.
2. Чанкование с учётом структуры документа.
3. Гибридный поиск: BM25 + векторы + reranking.
4. Генерация ответа со ссылками на источники.
5. Поддержка истории диалога (минимум 5 реплик).
6. UI или хотя бы REST API.

### Нефункциональные

1. Streaming ответа.
2. Логирование каждого запроса.
3. Eval-датасет ≥ 50 примеров + автоматический прогон.
4. Дашборд с latency, cost, % thumbs down.
5. Дoker Compose: запуск одной командой.

## Архитектура (рекомендуемая)

```
[Ingestion]  PDF/MD/HTML → parser → chunker → embeddings → pgvector
                                                ↓
[Query] question → query rewrite → hybrid search (BM25 + vec) → rerank → top-K
                                                                          ↓
[Generation] context + question → LLM → answer + sources → stream to user
                                                                          ↓
[Eval/Monitoring] Langfuse trace + offline evals в CI
```

## Этапы

1. **Неделя 1.** Ingestion + базовый чанкование. Загружаете 20–50 документов, считаете эмбеддинги, кладёте в pgvector.
2. **Неделя 2.** Retrieval baseline (только векторы, top-5) + простая генерация. Собираете eval-датасет.
3. **Неделя 3.** Hybrid search + reranking. Замеряете улучшение Recall@5 и faithfulness.
4. **Неделя 4.** UI, streaming, история диалога. Логирование, дашборд.
5. **Неделя 5.** Evals в CI, мониторинг, документация. Релиз.

## Метрики приёмки

- Recall@5 ≥ 0.80 на eval-датасете.
- Faithfulness (через LLM-as-judge) ≥ 0.85.
- p95 TTFT < 1.5 сек, p95 TTLT < 5 сек.
- Стоимость одного запроса измерена и задокументирована.
- README позволяет запустить локально за < 10 минут.

## Что положить в резюме

- "RAG-ассистент с гибридным поиском и reranking. Recall@5 = 0.86, faithfulness = 0.91 на корпусе из 200 документов."
- Ссылка на репозиторий, на демо-видео (1–2 минуты).
- Описание принятых решений (ADR): почему такая модель, такой подход к чанкованию.

## Распространённые ловушки

- Хорошие метрики на тренировочных вопросах, провал на новых — недо-purpurпредставлен валидационный набор.
- Faithfulness падает на длинных контекстах — lost-in-the-middle. Поднимайте reranking, уменьшайте top-K.
- Стоимость взлетает из-за частых ретраев structured output — упростите схему или смените provider.
