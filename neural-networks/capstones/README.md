# 🎯 Капстоны курса — три проекта в портфолио

Капстон — это проект, который вы делаете **полностью самостоятельно** и кладёте в свой GitHub. Это то, что вы показываете на собеседовании вместо разговоров о «прошёл курс».

После каждого крупного блока курса есть один капстон. Они построены так, чтобы максимально пересекаться с реальными задачами на работе.

## Структура

- [**Капстон 1. Своя классификация изображений end-to-end**](./01-image-classifier.md) — после блока 1-6. CNN + аугментации + грамотный train loop + ONNX-инференс + Streamlit-демо.
- [**Капстон 2. MiniGPT с собственным датасетом**](./02-mini-gpt.md) — после блока 7-12. BPE токенизатор + трансформер с нуля + обучение + генерация + базовый ChatGPT-стиль chat-template.
- [**Капстон 3. Production-ready RAG-ассистент**](./03-rag-assistant.md) — после блока 13-18. Embeddings + векторная БД + LLM + FastAPI + Docker + мониторинг.

## Принципы хорошего капстона

1. **README обязателен.** Что делает проект, как запустить, какие метрики получили, известные ограничения.
2. **Один git push до того, как начали писать код.** Сначала пустой репо с README, потом всё остальное. Это дисциплинирует.
3. **Воспроизводимость.** `requirements.txt` или `pyproject.toml`, `Makefile` или скрипт `run.sh`. Чтобы один `git clone && make train` всё запускал.
4. **Метрики.** Не «работает хорошо», а accuracy / F1 / BLEU / hit-rate на конкретном test-сете, который вы зафиксировали.
5. **Один-два графика.** Train/val loss. Confusion matrix. Примеры выхода. Хватит трёх картинок в README.
6. **Демо.** Если возможно — Hugging Face Spaces, Streamlit Cloud или просто скриншот с локального запуска.

## Что НЕ нужно

- Не показывайте «обучил YOLO на 100 эпох» без сравнения с baseline. Это не проект, это туториал.
- Не пишите README на 10 страниц. 1-2 страницы концентрированной пользы > 10 страниц текста.
- Не используйте 30 фреймворков «для красоты». Меньше зависимостей — меньше боли при поддержке.
