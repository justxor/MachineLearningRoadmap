# 05. Сбор данных: API, парсинг, выгрузки

Часть реальных задач начинается с получения данных. Их редко выкладывают в csv с аккуратными колонками.

## Источники

- Внутренние БД / хранилища (Postgres, ClickHouse, BigQuery).
- REST API (публичные и внутренние).
- Файлы: CSV, Parquet, JSON, Excel.
- Веб-парсинг (только где это легально).
- Потоки: Kafka, Kinesis.

## Инструменты

- requests, httpx (async).
- SQLAlchemy / asyncpg.
- BeautifulSoup, selectolax для HTML.
- Playwright для динамических сайтов.
- pyarrow для быстрых форматов.

## Правила работы с API

- Ретраи с экспоненциальным бэкоффом (tenacity).
- Рейт-лимиты: уважайте Retry-After.
- Пагинация: cursor-based надёжнее offset.
- Секреты в .env, не в коде.
- Кэшируйте локально при разведке.

## Юридические и этические вопросы

- ToS сайта. robots.txt.
- Персональные данные: GDPR/152-ФЗ.
- Коммерческие лицензии датасетов.

## Антипаттерны

- Не пишите «одноразовый» скрипт без логов.
- Не скачивайте всё в память без чанков.
- Не игнорируйте временные зоны.

## Практика

1. Соберите данные с любого открытого API (погода, крипта) за 30 дней.
2. Реализуйте retry + rate-limit через tenacity.
3. Напишите ingestion-скрипт, сохраняющий в partitioned parquet.
4. Оберните в CLI с typer/argparse.
5. Сделайте выгрузку из Postgres в parquet chunk’ами.
6. Напишите README с воспроизводимыми шагами.

## Чек-лист

- [ ] Секреты не в коде.
- [ ] Есть логи и retry.
- [ ] Данные хранятся в воспроизводимом формате.
