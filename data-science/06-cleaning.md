# 06. Очистка и валидация данных

Грязные данные — причина ½ ошибок моделей. Работа с данными = это не «скучная часть», это работа.

## Классы проблем

- Пропуски: MCAR/MAR/MNAR. Разные причины — разные стратегии.
- Дубликаты: полные, частичные, fuzzy.
- Выбросы: реальные vs брак ввода.
- Типы: числа-строками, даты-строками.
- Кодировки, разный регистр, пробелы.
- Временные зоны.
- Неконсистентные категории («Moscow» / «Москва» / «msk»).

## Подход

1. Сначала профилируйте: ydata-profiling / great-expectations.
2. Документируйте правила очистки в README или отдельном файле.
3. Очистка — воспроизводимая функция, не ручные правки.
4. Отделяйте raw → interim → processed.

## Валидация

- pandera, pydantic, great-expectations.
- Проверяйте: типы, диапазоны, уникальность ключей, regex для строк.
- Падайте рано: schema check на входе пирамиды.

## Антипаттерны

- Дропнуть NA «по умолчанию» — потерять большинство данных.
- Проставить медиану всюду — исказить распределение.
- Убрать «выбросы» по 3-сигма без анализа природы данных.

## Практика

1. На выбранном датасете профилируйте и выпишите 10 проблем.
2. Напишите cleaning.py с функциями + тестами.
3. Опишите схему в pandera.
4. Сравните стратегии импьютации пропусков.
5. Анализ выбросов: IQR, isolation forest. Объясните природу.
6. Сделайте fuzzy-дедуп через rapidfuzz.
