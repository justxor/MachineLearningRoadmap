# 🎤 Подготовка к ML-собеседованиям

Системная подготовка к собесам на позиции Junior/Middle/Senior ML / Data Scientist / LLM Engineer / MLOps Engineer. Без зубрёжки — с пониманием.

## 🎯 Цель этого модуля

Дать **рабочую базу** для прохождения 4–6 этапов типичного ML-собеседования: техскрининг, ML-теория, ML system design, coding, behavioral. Каждая тема — с вопросами и развёрнутыми ответами, чтобы вы не «учили формулировки», а понимали суть и могли защитить ответ.

## 🗓️ План подготовки на 4 недели

Если до собеседования 4 недели и вы уже работаете в ML — этого плана достаточно. Если нет опыта — добавьте ещё 4–8 недель на базу из основных курсов репозитория.

**Неделя 1 — техническая база:**
- Прочитать [01-ml-classic.md](./01-ml-classic.md) и [02-deep-learning.md](./02-deep-learning.md).
- Ответить вслух на все вопросы. На каждом «плыву» — открыть соответствующий урок в [neural-networks/](../neural-networks/README.md) или [data-science/](../data-science/README.md).
- 5 задач LeetCode medium в день.

**Неделя 2 — специализация:**
- Прочитать [03-llm-rag-agents.md](./03-llm-rag-agents.md) (если собес на LLM/GenAI).
- Перерешать 50 SQL-задач на [StrataScratch](https://stratascratch.com).
- Прочитать про реальные системы из вашего домена (компания + статьи).

**Неделя 3 — system design:**
- Прочитать [04-system-design.md](./04-system-design.md).
- Самостоятельно расписать 5 кейсов на доске/Miro: поиск, рекомендации, фрод, чат-бот, модерация.
- Найти товарища для mock-интервью.

**Неделя 4 — финал:**
- Прочитать [06-behavioral.md](./06-behavioral.md), подготовить 8–10 STAR-историй.
- Прогнать 3 mock-интервью (с друзьями или платно на [interviewing.io](https://interviewing.io)).
- Отдохнуть за день до собеседования. Хорошо поспать.

## 🧠 Принципы подготовки

1. **Понимание > запоминание.** Если можете объяснить тему 12-летнему — вы её знаете. Если только пересказываете определение из учебника — нет.
2. **Думайте вслух.** Интервьюер оценивает процесс мышления, не только финальный ответ. Молчание = провал.
3. **Не бойтесь сказать "не знаю".** Лучше честно признать пробел и предложить, как бы вы разобрались, чем выдумывать.
4. **Уточняйте вопрос.** «Какой контекст? Какие constraints? Какие данные?» — половина успеха в system design.
5. **Покажите trade-offs.** Не «X лучше Y», а «X выигрывает по A, проигрывает по B; в нашем контексте важнее A».
6. **Связывайте с опытом.** «Я делал похожее на проекте X, там сработало Y» — резко повышает доверие.

## 💰 Сколько спрашивают по уровням

| Уровень | Фокус собеса | Сколько готовиться |
|---------|--------------|-------------------|
| **Junior** | Coding + ML basics. Меньше system design, больше «понимаешь ли ты основы» | 2–4 недели |
| **Middle** | Equal weight: coding, ML/DL, простой system design, проекты | 4–6 недель |
| **Senior** | System design, leadership, архитектура. Coding есть, но проверяет ясность мышления | 6–8 недель |
| **Staff/Principal** | Стратегия, влияние, культура. ML — на уровне «могу собеседовать любого» | 8–12 недель + опыт |

## ❓ Что делать после отказа

Отказы — норма. Топовые инженеры получают 1 оффер из 5–10 собеседований.

1. **Запросите фидбек.** Не всегда дают, но иногда — да. Конкретика бесценна.
2. **Записывайте слабые места.** Если 3 раза проваливаете system design — это сигнал.
3. **Не воспринимайте лично.** Иногда дело не в вас, а в внутренних причинах компании.
4. **Не идите на следующий собес сразу.** Лучше 3 дня перерыв, чем выгоревший интервью.
5. **Считайте воронку.** 50 откликов → 10 собесов → 1 оффер = норма для джуна. Меньше отклика на собес — улучшайте резюме.

---

> 🎯 Собес — это навык, который тренируется отдельно от работы. Не бывает «я хороший инженер, поэтому пройду» — бывает «я готовился к собесу и поэтому прошёл». Готовьтесь системно.
