# 🏷️ Лаба 12: Извлечение сущностей (NER) для документов 🟡

## Цель

Извлечь сущности (имена, организации, даты, суммы, номера договоров) из документов для автоматизации бэк-офиса.

## Датасет

- CoNLL-2003 (базовый EN).
- Русский: NER-RuRoBERTa, factRuEval-2016.
- Свой датасет в формате BIO/BIOES, размеченный в doccano или Label Studio.

## Минимальный пайплайн

1. Подготовка данных в BIO.
2. AutoTokenizer + word_ids для выравнивания лейблов.
3. AutoModelForTokenClassification.
4. Trainer + seqeval метрики.
5. Пост-обработка: сборка сущностей из токенов.
6. Работа с длинными документами (chunking + overlap).

## Метрики

- F1-macro по сущностям (не по токенам!).
- Exact match per-entity-type.
- Strict mode (seqeval): только полные совпадения сущностей считаются.
- Baseline rule-based: F1 ~0.5; BERT-NER: F1 0.85+.

## Расширения

- LayoutLM для документов с layout (сканы).
- Few-shot NER через LLM с inst-promptami.
- Active learning: приоритизация сложных примеров.
- Нормализация: даты в ISO, суммы в числа.
- Linking к knowledge base.

## Критерии приёмки

- [ ] F1-macro >0.85.
- [ ] Per-entity-type метрики в таблице.
- [ ] Инференс на длинном доке (>1000 токенов) работает.
- [ ] Error analysis: 10 worst cases.
- [ ] Output в структурированном JSON.

## Анти-паттерны

- ❌ F1 по токенам вместо сущностей (в 5–10х выше).
- ❌ Игнор word_ids — лейблы сдвинуты.
- ❌ Обучение на «чистых» данных — модель падает на OCR-шуме.
- ❌ Не учитываются вложенные сущности.
