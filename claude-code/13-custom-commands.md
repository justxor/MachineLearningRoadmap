# 13. Кастомные slash-команды

## Зачем

Кастомные команды — это сохранённые промпты для повторяющихся рабочих сценариев. Вызываются `/command-name` внутри сессии. Стоят рядом с кодом, попадают в git — расшариваются на команду.

## Где хранятся

- `~/.claude/commands/` — личные, для всех проектов
- `.claude/commands/` в корне репо — проектные (в git)

Имя файла `<name>.md` → команда `/<name>`.
Подпапки допускаются: `.claude/commands/db/migrate.md` → `/db:migrate`.

## Формат

```markdown
---
argument-hint: <описание аргументов>
description: <одна строка>
---

<сам промпт на русском или английском>
Аргументы подставляются через $ARGUMENTS
```

## Примеры

### /commit

`.claude/commands/commit.md`:

```markdown
---
description: Разбить текущие изменения на логические коммиты
---

Сделай `git status` и `git diff --stat`.
Разбей изменения на логические группы.
Предложи план коммитов в Conventional Commits.
Ничего не коммить без моего ok.
```

### /review

```markdown
---
argument-hint: [pr-number]
description: Сделать ревью PR или текущей ветки
---

Сделай ревью изменений в PR #$ARGUMENTS (или в текущей ветке, если аргумент не дан).
Проверь:
- Баги и регрессии
- Покрытие тестами
- Стиль и размер функций
- Безопасность (SQL, secrets, prompt injection)
- Обратную совместимость

Ответ в формате: критичные / важные / нитпики.
```

### /tdd

```markdown
---
argument-hint: <описание фичи>
description: Цикл TDD: тесты → код → рефакторинг
---

Реализуй фичу: $ARGUMENTS

Шаги:
1. Напиши полный набор падающих тестов, включая edge cases.
2. Запусти тесты — убедись, что красные.
3. Реализуй минимальный код для зелёных тестов.
4. Рефактори. Тесты остаются зелёными.
5. Не skip-ай тесты. Не меняй expected.
```

### /db:explain

```markdown
---
argument-hint: <SQL или таблица>
description: Объяснить запрос / EXPLAIN ANALYZE
---

Через MCP Postgres выполни EXPLAIN ANALYZE $ARGUMENTS.
Объясни план, найди узкие места, предложи индексы или рерайт запроса.
```

## Команды с вызовом bash

В промпте можно использовать синтаксис вызова команды и подстановки файлов, чтобы автоматически вкладывать контекст. Например, можно вставить вывод `git diff` или содержимое конкретного файла в сам промпт перед отправкой.

## Организация

Команда-специфичные процессы:

```
.claude/commands/
  commit.md
  review.md
  tdd.md
  release.md
  db/
    migrate.md
    explain.md
    backup.md
  docs/
    update.md
    adr.md
```

## Практика

1. Создай `/commit` из примера выше, проверь в своём репо.
2. Напиши `/review` с аргументом номера PR.
3. Создай `/tdd` команду и используй для новой функции.
4. Сделай подпапку `db/` с двумя командами (проверь `/db:explain`).
5. Напиши `/onboard` — даёт новому разрабу обзор проекта.
6. Сделай `/release`: бамп версии, changelog, тег.
7. Добавь личные команды в `~/.claude/commands/` (`/explain`, `/plan`).
8. Переведи 5 своих частых ручных промптов в кастомные команды.

## Чек-лист

- [ ] 3+ команды в `.claude/commands/` репо
- [ ] 2+ личных в `~/.claude/commands/`
- [ ] Используешь $ARGUMENTS и подпапки
- [ ] Команды закоммичены и команда их видит
- [ ] Не дублируешь CLAUDE.md и команды
