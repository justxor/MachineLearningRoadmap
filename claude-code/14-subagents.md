# 14. Subagents и параллелизм

## Идея

Subagent — это отдельный экземпляр агента с собственным контекстом, ролью и набором инструментов. Основной агент делегирует им задачи. Это полезно в двух случаях:

1. **Параллельность** — несколько поисков/анализов одновременно без забивания основного контекста.
2. **Специализация** — отдельные роли для разных задач (security-review, db-expert, test-writer).

## Где хранятся

- `~/.claude/agents/` — личные
- `.claude/agents/` в корне репо — проектные

## Формат файла

```markdown
---
name: security-reviewer
description: Ревьюит код на уязвимости. Используй после каждой фичи в auth/payments.
tools: Read, Grep, Glob, Bash
model: opus
---

Ты — безопасник. Проверяешь код на:
- SQL injection, XSS, CSRF
- Небезопасные deserialization
- Секреты в коде
- Неправильную валидацию ввода
- Auth/authz ошибки

Для каждой находки: файл:строка, описание, severity (критичная/важная/нитпик), как починить.
Не пиши код сам. Только репорт.
```

Поля:

- `name` — имя, используется при вызове
- `description` — основной агент выбирает subagent по её смыслу. Пиши явно: «используй после X», «всегда для Y»
- `tools` — ограничение инструментов (по умолчанию — все)
- `model` — можно взять более сильную модель для сложных subagents

## Как вызываются

### Явно

```
> @security-reviewer проверь изменения в src/auth/
```

### Неявно

Если description совпадает с задачей, основной агент сам делегирует:

```
> Добавь эндпоинт /admin/users/delete.
→ Основной агент пишет код, потом сам вызывает @security-reviewer.
```

## Полезные subagents

### test-writer

Пишет тесты по файлу. Инструменты: Read, Write, Bash.

### docs-writer

По изменениям обновляет docs/. Различает «docs» (вывод) и «adr» (решения).

### data-explorer

Через Postgres MCP исследует данные, находит аномалии. Инструменты только: mcp__postgres__query.

### bug-hunter

По трейсу из Sentry находит файл и причину. Не правит код.

### release-manager

Бампит версию, пишет CHANGELOG, ставит тег.

## Параллельный запуск

```
> Запусти три subagent параллельно:
> - @data-explorer: посчитай активность за июль
> - @security-reviewer: проверь src/auth/
> - @docs-writer: сверь README с реальным поведением
> Сведи результаты.
```

## /agents

Интерактивный редактор subagents в сессии: создать, посмотреть, включить.

## Не злоупотребляй

- 1–3 subagent — оптимум
- 10+ — основной агент не понимает, кого вызывать, и начинает хаосить
- Subagent не видит CLAUDE.md основного агента — нужные правила пиши в промпте subagent
- Каждый subagent съедает токены — это не «бесплатно»

## Практика

1. Создай `security-reviewer` из примера выше.
2. Проверь его на реальном коде (лучше взять old файл с известными историческими багами).
3. Напиши `test-writer` с ограничением инструментов.
4. Создай `docs-writer`, протестируй на изменениях фичи.
5. Запусти 3 subagent параллельно по разным задачам.
6. Сравни итог: subagent vs прямой промпт основному агенту. Где выигрыш?
7. Добавь ограничение model: `sonnet` для лёгких subagent и `opus` для сложных.
8. Убери subagent, который не используется чаще раза в неделю.

## Чек-лист

- [ ] 2–3 subagent в репо
- [ ] Description явно описывает, когда вызывать
- [ ] tools сужены до нужного
- [ ] Запускал параллельно
- [ ] Не переходишь 5+ subagent
