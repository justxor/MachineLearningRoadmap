# 02. CLAUDE.md и контекст проекта

## Зачем нужен CLAUDE.md

Это файл-память в корне репозитория, который Claude Code автоматически подключает к каждой сессии. Без него агент каждый раз заново изучает проект и делает одни и те же ошибки.

Цель — дать агенту ровно тот контекст, который получает новый разработчик в первый день: стек, команды, соглашения, ловушки.

## Иерархия

Claude Code ищет CLAUDE.md в порядке:

1. `~/.claude/CLAUDE.md` — глобальные инструкции для всех проектов
2. `./CLAUDE.md` в корне репо — проектные
3. `./CLAUDE.local.md` — личные, в `.gitignore`
4. `./packages/*/CLAUDE.md` — подпапки в monorepo

Память складывается: глобальный + проектный + локальный.

## Что писать в проектный CLAUDE.md

**Полезно:**

- Стек (версии Node, Python, фреймворки)
- Как запускать (`npm run dev`, `make test`, порты)
- Как тестировать (один файл, весь проект)
- Архитектура в 5 строках (где что лежит)
- Соглашения: импорты, наименования, стиль коммитов
- Запреты: какие файлы не трогать, какие команды не запускать
- Ссылки на docs/ и ADR

**Бесполезно:**

- Пересказ README (агент и так его читает)
- Общие лозунги типа «пиши хороший код»
- Длинные списки библиотек (видны в `package.json`)

## Шаблон

```markdown
# Project: acme-api

## Stack
- Node 20, TypeScript 5.4, Fastify 4
- Postgres 15, Drizzle ORM
- Vitest для тестов

## Commands
- \`npm run dev\` — локальный сервер на :3000
- \`npm test\` — все тесты
- \`npm test -- src/users\` — один модуль
- \`npm run db:migrate\` — миграции

## Architecture
- src/routes/ — HTTP handlers
- src/services/ — бизнес-логика
- src/db/ — схема и запросы
- tests/ — тесты рядом с кодом (*.test.ts)

## Conventions
- Импорты через alias \`@/\` (см. tsconfig)
- camelCase в TS, snake_case в БД
- Коммиты: Conventional Commits

## Do not
- Не трогай миграции в db/migrations/applied/
- Не запускай \`npm run db:reset\` без подтверждения
- Не правь сгенерированные файлы в src/generated/

## See also
- docs/architecture.md
- docs/adr/ — решения по архитектуре
```

## Команда /init

В сессии выполни `/init` — агент сам прочитает репозиторий и сгенерирует черновик CLAUDE.md. Дальше правь руками: выбрось воду, добавь запреты и ловушки.

## # и #! — быстрое добавление памяти

Внутри сессии:

- `# всегда запускай тесты через npm test, а не vitest` — допишется в проектный CLAUDE.md
- `#! ...` — в глобальный

Так CLAUDE.md растёт органически из реальных ошибок, а не пишется впрок.

## Практика

1. Сделай `/init` в своём репозитории. Посмотри, что сгенерировалось.
2. Сократи файл до 30–50 строк. Убери всё очевидное.
3. Добавь блок «Do not» с 3–5 конкретными запретами.
4. Создай глобальный `~/.claude/CLAUDE.md` со своими привычками (язык общения, тон, всегда писать тесты).
5. Попробуй `#` в сессии: добавь правило «всегда запускай lint перед коммитом».
6. Для monorepo: создай подпапку CLAUDE.md в `packages/api/` и `packages/web/`.
7. Добавь `CLAUDE.local.md` в `.gitignore` и запиши туда личные предпочтения.
8. Через неделю работы пересмотри CLAUDE.md — убери то, что не сработало.
