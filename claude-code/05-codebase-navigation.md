# 05. Чтение и навигация по кодовой базе

## Основная идея

Claude Code не видит весь проект сразу. Он читает файлы по мере необходимости через grep, glob, Read. Твоя задача — навести его на нужные места и не дать прочитать 100% репозитория.

## Паттерны запросов

### Карта репо

```
> Нарисуй в ASCII карту каталогов верхнего уровня с пояснением по каждому.
> На вход приложения — от какого файла? Где он регистрирует роуты?
```

### Поиск фичи

```
> Где в коде логика логина? Покажи все файлы, участвующие в обработке POST /auth/login.
```

### Почему этот код

```
> @src/services/payment.ts Объясни, почему здесь retry с backoff в функции charge?
> Есть ли комментарии, ADR или коммиты, объясняющие это?
```

### История изменений

```
> Кто и когда последний раз менял src/db/migrations? Сделай `git log -p --follow` и резюмируй.
```

## Как не надо

- Не говори «прочитай весь проект» — это сжигает контекст и даёт поверхностный ответ.
- Не пиши «посмотри файл X», если не уверен — пусть сам ищет.
- Не выкладывай огромные файлы в @-контекст без необходимости.

## Инструменты агента

Агент сам выбирает:

- `Glob` — поиск файлов по маске (`**/*.test.ts`)
- `Grep` — регекс по содержимому (под капотом — ripgrep)
- `Read` — чтение файла целиком или диапазоном строк
- `Bash` — любые CLI: git, find, jq, awk

Он обычно начинает с grep по ключевым словам, потом читает найденные файлы. Это быстрее, чем чтение подряд.

## Большие монорепозитории

- Давай явные scope: «в папке packages/api»
- Добавь `CLAUDE.md` в каждый пакет
- Используй subagents для параллельного исследования нескольких модулей (см. урок 14)

## Знакомство с новым проектом — чек-лист

Спроси агента последовательно:

1. Стек, язык, фреймворки (из package.json/pyproject.toml).
2. Энтри-поинт приложения.
3. Схема БД или основные сущностьи.
4. Где тесты, как запускаются.
5. CI/CD и deployment.
6. Документация, ADR, README.
7. TOP-5 «грязных» мест (TODO/FIXME, большие файлы, дубли).

Сложи это в `docs/onboarding.md` — полезно для команды.

## Практика

1. В новом (незнакомом) репозитории пройди весь чек-лист выше.
2. Попроси нарисовать data flow одного endpoint от входа до БД.
3. Сделай `docs/onboarding.md` и коммитни.
4. Найди все места, где используется одна конкретная функция, без ручного указания путей.
5. Попроси найти все места с «deprecated» и сделай план для их удаления.
6. Используя git log, попроси резюме основных изменений за последний месяц.
7. Найди «мертвый код» (функции без вызовов).
8. Объясни самый сложный файл в проекте на уровне «для новичка».

## Чек-лист

- [ ] Умеешь формулировать scope вместо «прочитай всё»
- [ ] Используешь @-вкладывание осознанно
- [ ] Можешь получить карту нового репо за 5 минут
- [ ] Сделал onboarding.md хотя бы для одного проекта
