# 11. MCP: Model Context Protocol

## Основная идея

MCP — это открытый протокол от Anthropic, который позволяет LLM-клиентам (Claude Code, Claude Desktop, Cursor, IDE) подключаться к внешним системам через стандартизованный интерфейс.

Аналогия: USB-C для LLM. Один протокол — любые инструменты.

## Архитектура

- **MCP-клиент** — хост (Claude Code), который вызывает серверы.
- **MCP-сервер** — отдельный процесс, предоставляющий:
  - **tools** — функции, которые LLM может вызывать
  - **resources** — данные, которые он может читать
  - **prompts** — предварительные шаблоны

Транспорты: stdio (локальные процессы), SSE/HTTP (удалённые серверы).

## Что это даёт на практике

Без MCP агент работает только с файлами и bash. С MCP он может:

- Исполнять SQL в Postgres и читать результаты
- Открывать браузер через Playwright и видеть страницы
- Читать Sentry/Datadog трейсы
- Работать с Jira/Linear/GitHub Issues
- Подняться в файлы Figma

## Структура сервера

Сервер в stdio-формате выглядит как любой CLI-процесс, общающийся через JSON-RPC по stdin/stdout.

Минимальный пример на Python:

```python
from mcp.server.fastmcp import FastMCP

app = FastMCP("weather")

@app.tool()
def get_weather(city: str) -> str:
    return f"In {city}: sunny, 22°C"

if __name__ == "__main__":
    app.run()
```

Запуск: `python weather_server.py`. Дальше регистрируешь в Claude Code (см. урок 12).

## Ресурсы

```python
@app.resource("users://list")
def list_users() -> str:
    return open("users.json").read()
```

Агент может вкладывать ресурсы в контекст через @.

## Промпты

Шаблоны, которые сервер предоставляет клиенту. Пользователь может выбрать их из меню — удобно для повторяющихся рабочих процессов.

## Безопасность MCP

MCP-сервер — это произвольный код, который ты запускаешь. Работает с твоими ключами и имеет полный доступ к данным, которые ему даёшь.

Правила:

- Ставь только серверы из известных источников
- Читай исходный код перед запуском
- Для Postgres MCP используй read-only пользователя на staging
- Секреты передавай через env, не в файлах конфига
- Prompt injection в ответах MCP — реальная угроза (чужие issue, логи, web-страницы)

## Официальные ресурсы

- modelcontextprotocol.io — спецификация
- github.com/modelcontextprotocol/servers — референсные серверы
- Сообщество: большой каталог серверов от разных вендоров

## Практика

1. Прочитай спецификацию MCP на modelcontextprotocol.io.
2. Запусти референсный сервер `@modelcontextprotocol/server-filesystem` с `npx`.
3. Напиши свой минимальный сервер (Python или TypeScript) с одним инструментом.
4. Добавь в него resource с содержимым локального файла.
5. Опиши prompt в своём сервере.
6. Проверь работу через inspector (mcp dev / @modelcontextprotocol/inspector).
7. Подумай: какой из твоих внутренних инструментов имеет смысл обернуть в MCP?
8. Нарисуй в блокноте схему: Claude Code ↔ MCP ↔ внешняя система.
