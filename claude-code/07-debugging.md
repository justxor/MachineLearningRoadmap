# 07. Отладка и поиск багов

## Принцип

Отладка — это воспроизведение ошибки, изоляция, исправление, проверка. Агент хорош на всех этапах, но тебе нужно давать ему факты, а не догадки.

## От симптома к причине

Не спрашивай: «почини логин». Спроси:

```
> Логин падает с 401 только для пользователей, созданных до миграции v23.
> Ошибка из лога: "bcrypt: invalid hash format".
> @src/auth/login.ts @src/auth/password.ts
> Предположи причину, подтверди тестом, потом предложи исправление.
```

Ключевое: симптом + воспроизведение + файлы + требование доказать гипотезу.

## Метод бисекции

Баг был в прошлой версии? Попроси:

```
> Сделай `git bisect` между тегом v1.4.0 (работал) и HEAD (сломан).
> Скрипт проверки: `npm test -- auth/login`.
```

## Логи и трейсы

```
> Добавь временно console.log в ключевых точках (вход в функцию, вызов BD, ответ).
> Запусти воспроизведение, покажи логи.
> После фикса — убери логи.
```

## Производственные инциденты

Есть Sentry/Datadog через MCP — агент сам подтянет трейс:

```
> Посмотри в Sentry ошибку EX-1234. Найди в коде файл из трейса, объясни причину, предложи фикс.
```

## Что не работает

- «Почини это» — агент может внести косметический фикс без понимания причины
- «Игнорируй тест» — спрячет проблему
- Общие try/catch вокруг сломанного куска — то же

Признаки «фальшивого» фикса: появились try/catch без обработки, изменён тест, вместо кода, добавлен default в if/else «на всякий случай».

## Правило: регрессионный тест

На каждый баг — тест, который падал бы без фикса.

```
> Сначала напиши тест, который воспроизводит баг и падает. Потом почини код.
```

## Практика

1. Выбери реальный баг (свой или из issues).
2. Сформулируй воспроизведение в 3 строках.
3. Попроси агента выдвинуть 3 гипотезы и проверить каждую.
4. Попроси сначала написать падающий тест, потом фиксить.
5. Сделай `git bisect` последнего regression в своём проекте.
6. После фикса выполни «постмортем»: просьба агенту перечислить все похожие места в коде, где эта ошибка может повториться.
7. Научись различать «починил» и «замаскировал».
8. Подключи Sentry через MCP (см. урок 12).

## Чек-лист

- [ ] Даёшь симптом, воспроизведение, файлы
- [ ] Требуешь доказательство гипотезы
- [ ] Регрессионный тест на каждый баг
- [ ] Не принимаешь «спрятанные» фиксы
- [ ] Используешь git bisect для regression
