# 09. Рефакторинг и миграции

## Основное правило

Рефакторинг — это изменение структуры без изменения поведения. Тесты проходят до и после. Если тестов нет — сначала тесты.

## Классы рефакторинга для агента

### Локальный

Переименовать, выделить функцию, разбить файл. Агент делает это отлично в 1 проход.

### Кросс-файловый

Поменять API модуля и все места вызова. Нужен явный план и поиск всех use-sites.

### Системный

Смена фреймворка, ORM, ruнтайма. Делится на этапы, каждый — отдельная сессия.

## Шаблон: «безопасный рефакторинг»

```
> Переименуй ChargeService в PaymentService во всём репо.
> Правила:
> 1. Никаких изменений поведения.
> 2. После каждого файла запускай `npm run typecheck`.
> 3. В конце запусти все тесты. Не принимай «зелёный» без фактического запуска.
> 4. Сделай отдельные коммиты: rename, fix imports, update tests, docs.
```

## codemod вместо ad-hoc

Для повторяющихся изменений (замена API в 100+ файлах) попроси агента написать codemod на jscodeshift / libcst:

```
> Напиши jscodeshift transform: заменить все `db.query(SQL, args)` на `db.execute({sql: SQL, params: args})`.
> Сначала запусти в dry-run на 5 файлах, покажи результат.
```

Это детерминированно и ревьюится легче 100 ручных правок.

## Strangler pattern

При миграции:

1. Добавь новый код рядом со старым.
2. Переключай вызовы по одному.
3. Когда старый никто не вызывает — удаляй.

Не доверяй «я всё переписал» в одном коммите.

## Миграции БД

```
> Добавь поле email_verified в users.
> Шаги:
> 1. SQL-миграция (файл в db/migrations/, номер следующий по порядку).
> 2. Обнови ORM-схему.
> 3. Сделай backfill для старых пользователей (считай verified=true если created_at < cutoff).
> 4. Покажи rollback-миграцию.
```

## Обратная совместимость

При смене публичного API:

- Старый endpoint отмечается deprecated и логирует вызовы
- Новый вводится параллельно
- Через неделю/месяц — удаление

Агент по умолчанию любит «заменить сразу». Явно требуй deprecation path.

## Практика

1. Сделай rename ключевого сервиса по всему репо со всеми правилами выше.
2. Напиши codemod, который заменяет синхронные fs-вызовы на асинхронные.
3. Извлеки один модуль в отдельный пакет (`packages/utils`).
4. Сделай миграцию БД с backfill и rollback.
5. Проведи deprecation старого endpoint: добавь заголовок Deprecation, loги, новый endpoint.
6. Попробуй «большой рефакторинг»: разбей на 5–10 малых коммитов.
7. После рефакторинга запусти mutation testing — выжившие мутанты покажут «дыры» в тестах.
8. Проверь, что bundle size не вырос (если это front-end).
