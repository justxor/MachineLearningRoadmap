# 08. Тесты и TDD с агентом

## Почему тесты критичны для агента

Агент без тестов пишет «код, который выглядит правильно». С тестами — «код, который работает». Разница огромная.

Тест — это внешний оракул. Агент может итерировать до зелёных тестов без твоего участия.

## TDD-цикл с Claude Code

### Red

```
> Напиши падающий тест для функции parseEmail(input).
> Кейсы: пустая строка, без @, с unicode в локальной части, валидный, с пробелами по краям.
> Саму функцию не реализуй.
```

### Green

```
> Реализуй parseEmail минимальным кодом, чтобы все тесты стали зелёными.
```

### Refactor

```
> Рефактори реализацию: вынеси валидацию в отдельные функции. Тесты должны остаться зелёными.
```

## Цикл «зелёные тесты»

```
> Запускай npm test после каждого изменения.
> Если красные — чинишь, перезапускаешь. Не останавливайся, пока все зелёные.
> Не skip-ай тесты. Не меняй expected-значения без моего подтверждения.
```

Эти два правила в последней строке — обязательные. Без них агент любит приводить тесты в зелёный вид «хитрым способом».

## Property-based и fuzz

```
> Напиши property-based тесты для sortInts: результат той же длины, все элементы сохранены (multiset), порядок неубывающий.
> Используй fast-check.
```

## Когда мокать

- Сеть, БД, FS — да
- Случайность, время — да
- Логику внутри модуля — нет (иначе тест = пересказ реализации)

## Когда агент «жулит»

Симптомы:

- Появился `.skip` или `it.only`
- Ожидания изменены под реализацию
- Добавлены «if (testEnv)» ветки в продакшн-коде
- Снижен coverage threshold

Ревьюй дифф перед коммитом.

## Снапшоты

Подходят для больших структур (сериализация, AST). Агент любит обновлять снапшоты без проверки. Явно запрети:

```
> Не обновляй snapshot-файлы без моего подтверждения.
```

## Практика

1. Выбери функцию без тестов, попроси написать полный набор тестов (включая edge cases).
2. Реализуй новую функцию в TDD: сначала тесты, потом код.
3. Возьми падающий тест из реального CI — попроси починить без изменения самого теста.
4. Напиши property-based тест на чистую функцию (сортировка, парсинг, сериализация).
5. Проверь, что агент не ввёл `.skip` / `it.only` (grep по репо до коммита).
6. Настрой coverage threshold в CI и запрети понижать его в CLAUDE.md.
7. Сделай mutation testing (`stryker` или `mutmut`) на одном модуле.
8. Попробуй `/clear` перед писанием тестов — они получатся подлиннее.

## Чек-лист

- [ ] TDD-цикл Red-Green-Refactor освоен
- [ ] Запрет на skip в инструкциях
- [ ] Coverage threshold в CI
- [ ] Ревьюишь изменения в тестах не менее внимательно, чем в коде
- [ ] Property-based хотя бы в 1 модуле
